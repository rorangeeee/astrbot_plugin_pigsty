# astrbot_plugin_pigsty

Pigsty 是一个独立于 AstrBot 部署目录的群友小猪圈插件项目。

## 第一阶段

- 提供可加载的 `PigstyPlugin` 骨架和 `pig status` 基础命令。
- 使用 Pydantic v2 严格模型保存小猪状态。
- 使用按平台、主人和作用域隔离的原子 JSON 仓储。
- 不实现喂食、玩耍或 LLM 自然语言解析。

## 当前命令

- `pig status`：查看数据层状态和当前作用域。
- `pig add [名字]`：在调用者自己的猪圈中添加一只独立小猪；省略名字时自动命名，名字支持空格，独立小猪可以重复添加。生成时初始数值按概率随机（见下）。
- `pig add @用户 [名字]`：在调用者自己的猪圈中添加一只与目标用户关联的小猪；省略名字时自动命名，名字支持空格。被 @ 用户只作为小猪的关联属性，不会成为数据库主人；同一数据库内相同平台和用户的关联组合不能重复添加。生成时初始数值按概率随机（见下）。
- `pig rename 序号 新名字`：按 `pig show` 中从 1 开始的序号改名；名字支持空格，不展示内部 UUID。
- `pig diary [序号]`：查看最近 10 条值得记录的事件（不含例行事件）。不带序号时展示整个猪圈的事件；带序号时只展示该小猪的事件。
- `pig show`：按保存顺序查看调用者猪圈中的小猪及基础状态，不展示内部 UUID。猪圈为空时会提示 `你的猪圈还是空的，使用 pig add 添加一只小猪吧。`

未知命令会提示：`用法：pig status | pig add [@用户] [名字] | pig rename <序号> <新名字> | pig diary [序号] | pig show`。

## LLM 自然语言互动

插件会监听所有普通对话（`pig` 命令除外）。当调用者猪圈不为空时：

1. 先调用 AstrBot 默认对话大模型判断该消息是否包含对**该调用者自己猪圈中现有小猪**的具体行为（如喂食、玩耍、抚摸、洗澡等）；普通聊天、询问状态或不涉及现有小猪的消息不会触发后续处理。
2. 判定涉及小猪行为后，再调用默认对话大模型，把当前每只小猪的名称、显示序号、体重/健康/心情/体力最新值以及全局数值约束一起传入提示词，要求模型只返回结构化 JSON 数值变化。
3. 插件只接受模型返回的数值偏移，并在写入时把最终数值夹紧到全局限制：健康/心情/体力 `0–100`，体重 `>= 0.01kg`（无上限）；`age_days` 不会被用户互动改变。
4. 成功应用后，每只受影响小猪会新增一条 `user_events` 结构化日志，`pig diary` 可直接查看；模型生成的用户回复会原样发回当前会话。

两次 LLM 调用均使用 AstrBot 默认对话大模型且不携带插件人格设定；分类或转换失败时不会修改任何小猪数据。

## 初始数值随机

每只小猪生成时，体重、健康、心情、体力四项数值各自独立掷点（年龄保持 0 天），偏移方向双向随机：

| 概率 | 偏移幅度 | 播报 |
| --- | --- | --- |
| 75% | 不超过 5% | 不标记 |
| 15% | 5%–20% | 标记 |
| 8% | 20%–50% | 标记 |
| 2% | 50% 起，无上限 | 标记 |

2% 档在模型全局约束内取值：健康/心情/体力落在有效区间 `[0, 基准×50%]` 或 `[基准×150%, 100]` 内均匀随机；体重只有下限（>0kg），正侧按重尾分布采样、字面上没有上限（均值约 3.5 倍基准，极端值概率按指数衰减）。健康/心情/体力四舍五入为整数并夹紧到 0–100；体重保留两位小数、最小 0.01kg。

任一数值落出 75% 正常档时，`pig add` 播报追加标记，例如：

```text
已添加独立小猪：小猪-1a2b3c4d（体质异变：体重 7.5kg，心情 45）
```

## 时间演化与事件

每天 GMT+8 早上 9:00，系统自动对所有猪圈执行一次例行演化（插件启动时若当天 9:00 已过会立即执行；停机多天后恢复时一次性补满所有错过的天）。每只小猪每天：

| 数值 | 规则 |
| --- | --- |
| 年龄 | 每天 +1 |
| 体重 | 每天增长，增量在 (0, 1kg] 内随机 |
| 心情 | 每天随机偏移 ±5 以内，夹紧到 0–100 |
| 健康 | 每天随机偏移 ±3 以内，夹紧到 0–100 |
| 精力 | 每天在 0–100 内完全随机 |

- 每次真实触发都会**实时**为每只被演化的小猪记录一条例行事件（多天补进度也合并为一条，描述为净值汇总），写入对应数据库的 `events` 列表。
- 事件按类别记录：例行事件 `regular_events`（只能由系统触发，用户不可触发）；`unexpected_events`（突发事件）与 `user_events`（用户事件）为后续功能预留。
- `pig diary` 展示最近 10 条值得记录的事件（**不含例行事件**），例行事件只用于数据留痕。
- 幂等保证：同一 GMT+8 自然日内每只小猪最多演化一次（按 `last_state_update_at` 判断）。

## 突发事件

每只小猪独立掷骰，每天（与例行演化同一天概念，9:00 触发判定）有 20% 概率遭遇突发事件；当天未触发则第二天概率 +10%（20%→30%→…→100%），触发后重置回 20%（pity 状态存于小猪自身）。触发的小猪：

1. 随机影响 1 或 2 项数值（各 50% 概率，两项不重复）；每项受影响数值**独立**按四档概率偏移（相对当前值、双向随机）：

   | 概率 | 偏移幅度 |
   | --- | --- |
   | 75% | 当前值 ±5% 以内 |
   | 15% | 5%–20% |
   | 8% | 20%–50% |
   | 2% | 50% 起，无上限：模型约束内随机（健康/心情/精力在有效区间均匀；体重无上限，重尾分布） |

   应用时夹紧到模型边界；
2. 插件向默认对话大模型发起一次**不带人格设定**的询问，仅发送小猪名字、变化项与数值和构造请求 prompt，模型只回复事件描述（失败时回退为数值变化摘要）；
3. 事件写入小猪数据库（`unexpected_events`），并在当天 9:00–18:00 间随机时刻把推送模板消息发到猪圈所在会话（群猪圈发群、私聊猪圈私聊主人）。

推送模板示例：

```text
⚠️ 突发事件：1. 白雪 小猪
白雪 小猪在泥坑里摔了一跤，沾了一身泥。
（数值变化：体重 +0.53kg，心情 -3）
```

## 数据归属与作用域

- 每位命令调用者拥有自己的数据库，所有添加和查看操作都以调用者为准。
- `global` 作用域按平台和调用者隔离；`group` 作用域还会按群组隔离。

## 本地验证

```powershell
uv sync
uv run pytest -q
uv run ruff format --check .
uv run ruff check .
uv run basedpyright
```

插件运行时由 AstrBot 提供 `astrbot.*` 依赖；`core/` 不依赖 AstrBot，因此可以独立测试。
